# sanad — Frontend

React + Vite + TypeScript، ينشر على Netlify تلقائياً مع كل `push` على `main`.

الباك اند (قواعد Firestore) في ريبو منفصل: [sanad-backend](https://github.com/sanadgrid/sanad-backend).

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local   # ثم عبّي قيم Firebase
npm run dev
```

قيم Firebase من: Firebase Console ← ⚙ Project settings ← Your apps ← Web app ← SDK setup and configuration.

## ربط Netlify (مرة واحدة)

1. Netlify ← **Add new site** ← **Import an existing project** ← GitHub ← اختر `sanadgrid/sanad-frontend`.
2. إعدادات البناء تنقرأ تلقائياً من `netlify.toml` (الأمر `npm run build`، المجلد `dist`).
3. Site configuration ← **Environment variables** ← أضف متغيرات `VITE_FIREBASE_*` الستة الموجودة في `.env.example`.
4. Deploy. بعدها أي push على `main` ينشر تلقائياً، وأي Pull Request ياخذ رابط معاينة.
5. Firebase Console ← Authentication ← Settings ← **Authorized domains** ← أضف دومين Netlify.

> لو فشل البناء برسالة "secrets scanning" بسبب مفتاح يبدأ بـ `AIza`: مفتاح Firebase للويب عام بطبيعته (الحماية من قواعد Firestore). أضف في Netlify متغير `SECRETS_SCAN_SMART_DETECTION_OMIT_VALUES` وقيمته هي المفتاح.

## هيكلة الكود — طبقات

كل طبقة تستورد من اللي تحتها فقط، مو العكس:

```
src/
  app/        غلاف التطبيق: التوجيه والـ providers
  features/   شاشات ومزايا، كل ميزة في مجلدها (features/home, ...)
  components/ مكونات واجهة مشتركة بين المزايا (Logo, Icon) — بدون بيانات
  services/   الوصول للبيانات — المكان الوحيد اللي يكلم Firestore
  lib/        تهيئة البنية التحتية (firebase.ts للتطبيق وتسجيل الدخول، firestore.ts لقاعدة البيانات)
```

- نصوص وأرقام الصفحة الرئيسية كلها في `src/features/home/content.ts` — عدّلها هناك بدون لمس التصميم.
- ألوان وخطوط الهوية في `src/index.css`، وملفات اللوقو الجاهزة في `public/brand/`.
- صورة المشاركة (واتساب وغيره) هي `public/og-image.jpg` ووسومها في `index.html`. الرابط الكامل ينحقن وقت البناء من متغير `URL` حق Netlify (شوف `vite.config.ts`). المعاينة ما تظهر إلا والموقع Public.
- المكونات في `features/` ما تستدعي Firestore مباشرة؛ تنادي دوال من `services/`.
- أي collection جديدة = ملف في `services/` هنا + قاعدة في `firestore.rules` في ريبو الباك اند.
- مفاتيح الـ AI أو أي سر ما تنحط هنا أبداً — كل شي في الفرونت مكشوف للمتصفح. استدعاءات الـ LLM تمر عبر Cloud Function في ريبو الباك اند.

## لوحة قدرة استعادة الخدمة — `/restoration`

لوحة تخطيط تشغيلي: **الشبكة اللي تعرضها اللوحة هي خطط التغذية البديلة نفسها**. كل خطة = عنصر رئيسي (محطة أو مغذي) وحمله + بدائله بالترتيب وأحمالها، واللوحة تحسب كم من حمل الرئيسي تقدر بدائله تشيله لو فُقد لحاله، وترسم النتيجة على الخريطة فوق الطبقات المستوردة.

- **الصفحة خاصة** — ما تفتح إلا لمستخدم مسجّل دخوله ومصرّح له (التفاصيل في «الصفحة خاصة — بوابة الدخول» تحت).
- الكود كله في `src/features/restoration/`. `src/app/App.tsx` يحمّل **البوابة** فقط عند الطلب (`RestorationGate.tsx`)، والبوابة هي اللي تحمّل اللوحة (`RestorationPage` ومعها Leaflet وFirestore) بعد ما يتأكد التصريح.
- **مصدر بيانات اللوحة** = مستند الخطط `backupPlans/{sectorId}` (قراءة وحدة عند فتح الصفحة) + فهرس المحطات حق الطبقات المستوردة (للمواقع). الاشتقاق كله دوال صافية: `backup/model.ts` (الحساب) ثم `backup/planNetwork.ts` (المحطات والروابط والمؤشرات والتغطية) ثم `backup/planFilters.ts` — التفاصيل في «الشبكة المشتقة من الخطط» تحت.
- **ما فيه شبكة مصطنعة في الواجهة**: الدوائر التسعة عشر القديمة انشالت لأنها كانت تنفهم كمحطات فعلية. ملفاتها باقية في الريبو **لاستيراد مستوى المغذيات مستقبلاً** وما يستوردها أي شي من اللوحة، فما تدخل ملفات النشر: `engine.ts` (محرك مستوى المحطة MVA) و`demoData.ts` و`types.ts` واختباراتها، و`backup/fromNetwork.ts` + `components/FeederCard.tsx` (بطاقة «عند فقد المغذي»)، و`services/restoration.ts` + `services/networkBundle.ts` (حزمة الشبكة).
- **سجل القطاعات** في `sectors.ts`: اسم القطاع ومركز الخريطة وجدول التخفيض الحراري الشهري وسعة القاطع الافتراضية **مبنية في الكود** بقيم معقولة، فاللوحة ما تعتمد على مستند `sectors/{id}`. لو المستند موجود ياخذ منه **الاسم فقط** (وقطاعات زيادة ما يعرفها السجل).
- القراءة والكتابة في `src/services/` فقط. ما فيه أي قراءة بدون تسجيل دخول: القواعد ترفض الكل إلا المشرف أو عضو القطاع.
- خريطة الأساس OpenStreetMap معتّمة بـ CSS. لو عندك مفتاح لمزوّد خرائط داكنة حط رابطه في `VITE_MAP_TILE_URL` (شوف `.env.example`).

> **البيانات الفعلية ما تنحط في هذا الريبو أبداً** — الريبو عام وكل شي فيه مكشوف. البيانات الفعلية تنكتب على Firestore فقط، من مشرف مسجّل دخوله (له مستند في `admins/{uid}`)، وبـ `visibility: 'restricted'` عشان ما يقرأها إلا أعضاء القطاع.

### الصفحة خاصة — بوابة الدخول

`/restoration` ما تعرض أي شي — لا خريطة ولا مؤشرات ولا بيانات تجريبية ولا حتى كود اللوحة — إلا بعد شرطين: المستخدم **مسجّل دخوله** و**مصرّح له**.

**كيف ينعطى التصريح** (من Firebase Console ← Firestore، قاعدة `sanadgrid`، والـ uid من Authentication ← Users):

- **مشرف**: مستند `admins/{uid}` (فاضي يكفي). ينشأ من الـ Console فقط — القواعد تمنع كتابته من أي مكان ثاني. يشوف كل القطاعات ويقدر يكتب.
- **عضو**: مستند `members/{uid}` فيه `sectors: ["central", ...]`. يشوف القطاعات اللي في قائمته فقط (وهي اللي تطلع له في قائمة «القطاع»)، وما يكتب شي. `sectors` فاضية أو مو موجودة = غير مصرّح.
- التغيير يسري من الجلسة الجاية (المستخدم يقفل التبويب أو يسجّل خروج ويرجع)، وسحب التصريح يسري فوراً على القراءة لأن القواعد هي اللي تقرر — وأول قراءة تنرفض ترجّع المستخدم للبوابة.

**حالات البوابة** (`RestorationGate.tsx` — بطاقة وحدة في النص، بالوضعين الفاتح والداكن):

| الحالة | اللي يطلع |
| --- | --- |
| جارٍ التحقق | الشعار ومؤشر انتظار هادئ فقط |
| غير مسجّل | «هذه الصفحة مخصصة للمستخدمين المصرّح لهم» + زر تسجيل الدخول بحساب Google + رابط للرئيسية — بدون أي تلميح عن محتوى الصفحة |
| مسجّل وغير مصرّح | «حسابك غير مصرّح له…» + بريد الحساب + «تجربة حساب آخر» و«تسجيل الخروج» + «تواصل مع مسؤول النظام» |
| تعذّر التحقق (نت/حصة/مهلة) | «تعذّر التحقق من الصلاحية الآن» + «إعادة المحاولة» — **ما تنحسب أبداً تصريح** |
| نسخة بدون إعدادات Firebase | «هذه الصفحة غير متاحة حالياً» |

- **الفحص** في `src/services/access.ts` (منطق صافي ومختبر) والقراءتين في `accessReads.ts`: `admins/{uid}` أولاً، ولو مو مشرف `members/{uid}`. الكلفة: **قراءة وحدة للمشرف، قراءتين لغيره، مرة في الجلسة**. الـ«نعم» بس تنحفظ في `sessionStorage` (`sanad.rc.access.<uid>` — مربوطة بالحساب)، والـ«لا» تبقى لين تتقفل الصفحة، والفشل ما ينحفظ أبداً. الفحوصات المتزامنة تتشارك قراءة وحدة. هذا كله يقرر **اللي ينعرض** فقط — اللي ينقرأ فعلاً تقرره قواعد Firestore، فلو أحد عبث بالمتصفح ما يوصل لشي.
- **اللي ينزّله غير المسجّل**: الصفحة الأساسية + البوابة + مكتبة تسجيل الدخول. ملفات اللوحة وLeaflet وFirestore ما تنطلب إلا بعد التصريح (مجموعات `codeSplitting` في `vite.config.ts` تفصل `firebase` عن `firestore` لهالسبب). ونوافذ المشرف (استيراد الطبقات، الإدخال الجماعي، حذف البيانات القديمة) كل وحدة ملف لحالها ينطلب أول ما تنفتح.
- **تسجيل الخروج** من داخل اللوحة يرجّع للبوابة فوراً ويمسح كل اللي انقرأ: القطاعات وفهرس الطبقات والخطط من `localStorage` والذاكرة، وتصريح الجلسة من `sessionStorage` (`clearDataCache` في `cache.ts`). تفضيلات الشكل (الوضع، وضوح الخريطة) تبقى.
- **ما ننشر عنوان الصفحة**: ما فيه رابط لها في الصفحة الرئيسية، و`netlify.toml` يرسل `X-Robots-Tag: noindex, nofollow` لـ `/restoration`، والبوابة تضيف `<meta name="robots">` طول ما الصفحة مفتوحة، وعنوان التبويب يبقى «سند | SanadGrid» لين يمر المستخدم من البوابة.
- **الاختبارات بدون Firebase**: `npm test` يختبر منطق التصريح والكاش بدون أي اتصال. واختبارات المتصفح تشتغل على نسخة مبنية **بدون مفاتيح Firebase** — وهذي النسخة تطلع فيها البوابة بحالة «غير متاحة»، فلها مفتاح اختبار `VITE_E2E_OPEN=1` يفتح اللوحة **فاضية** (بدون خطط ولا طبقات — ما فيه حساب يقرأ منه)، و`?gate=signedOut|denied|unverified|checking` يعرض حالات البوابة للتصوير. أي اختبار يحتاج بيانات يحقن بيانات **مصطنعة** عبر خطّاف مؤقت ينشال قبل التسليم (الخطط والطبقات والحذف كلها تاخذ «مخزن» بديل: `PlanStore` و`LayerSource` و`LegacyStore`). المفتاح **ما يشتغل إلا والمفاتيح غايبة**: `vite.config.ts` يحوّله لـ `false` ثابتة في أي نسخة فيها مفاتيح، فكوده أصلاً ما يدخل نسخة الإنتاج.

### الشبكة المشتقة من الخطط — مصدر بيانات اللوحة

- **الطريقة** (`backup/model.ts`): نفس طريقة جدول فريق التشغيل حرفياً. عنصر رئيسي حمله `C`، وبدائل أحمالها `a1..an`، وسعة قاطع `R` (الافتراضي 400 أمبير): المتاح عند كل بديل `max(0, R − a)`، القابل للاستعادة `min(C, Σ المتاح)`، والتحويل يتوزع على البدائل بالترتيب وبنسبة المتاح عند كل واحد. التصنيف: 100% / 70% فأكثر / أكثر من صفر / صفر. الخيارات: `ratingA` و`derating` (يضرب السعة؛ 1 = طريقة الجدول كما هي). التحويل بين الأمبير وMVA وMW في مكان واحد: `backup/units.ts` (`√3 · kV · A / 1000`، ومعامل قدرة 0.9).
- **اختبار المعايرة** (`backup/model.test.ts` والبيانات في `backup/model.fixture.ts`): مثال الفريق المصطنع (30 مغذي في 3 قطاعات) لازم يطلع بالضبط: مجموع الأحمال 8,755 أمبير، غير القابل للاستعادة **525 أمبير**، النسبة **94.0%**، التصنيف 9 كامل / 21 مرتفع — ومع سعة 348 أمبير (= 400 × 0.87) يصير 3,475 (60.3%)، ومع 320 يصير 5,155 (41.1%). ونفس الأرقام لازم تطلع من مؤشرات اللوحة (`backup/planNetwork.test.ts`).
- **الاشتقاق** (`backup/planNetwork.ts` — دالة صافية `derivePlanNetwork(cases, directory, options)`):
  - **محطة** لكل عنصر مختلف (برقمه + نقطته بالضبط) يظهر في أي خطة. اللي هو **رئيسي** في خطة يحمل نتيجتها (النسبة، التصنيف، الحمل وغير القابل للاستعادة بالأمبير وMVA) — ولو له أكثر من خطة يحمل الأضعف. واللي يظهر **كبديل فقط** يحمل حمله، وتحميله الحين، و**أسوأ حالة**: أعلى تحميل يوصله بين الخطط اللي يدعمها — كل حالة لحالها (فقد واحد)، مو مجموعها.
  - **رابط** لكل (بديل ← رئيسي) بالأمبير المنقول وتحميل البديل بعده؛ البديل المشترك بين رئيسيين له رابط لكل واحد.
  - **مؤشرات القطاع** (`summarizeRows`): النسبة موزونة بالحمل، مجموع الأحمال (A وMVA)، غير القابل للاستعادة (A وMVA وMW)، عدد الخطط الأقل من 100%، عدد البدائل اللي تتجاوز سعتها، و**التغطية** «n من m محطة لها خطة» (m = محطات الفهرس المستوردة) — هذا الرقم يقول كم من الشبكة الفعلية دخل الحساب لين الحين.
  - العنصر اللي رقمه مو في الفهرس وما له نقطة `at` ينحسب في المؤشرات وينذكر في إشعار «بدون موقع» وما ينرسم؛ واللي رقمه له أكثر من موقع وما انحدد ينذكر «بحاجة إلى تحديد الموقع».
- **الخريطة** (`components/planNetworkLayers.ts`): نفس لغة الشبكة القديمة — دوائر بلون التصنيف وحافة بيضاء وحجمها بالحمل، الرقم + النسبة من تكبير 11، هالة تنبض على المحدود والمعدوم، تلميح عند المرور، وضغطة تفتح التفاصيل. الروابط دايماً ظاهرة ولونها بتحميل البديل النهائي (هادي لين 80%، كهرماني 80–100%، أحمر فوق)، والحركة والأمبيرات على روابط الخطة المختارة فقط. البديل-فقط حلقة صغيرة محايدة ومعها أسوأ تحميل له. الخريطة ما تنعاد إنشاؤها مع تغيّر البيانات أو الوضع أو التصفية، والطبقات المستوردة تبقى تحتها.
- **الافتراضات** (أهم فكرة): مفتاح واحد «تطبيق التخفيض الحراري» + شهره + سعة القاطع يعيدون حساب كل شي فوراً **بدون ولا قراءة** — ويظهرون دايماً كشرائح صغيرة جنب العنوان. أي أحد يقدر يجرّب سعة ثانية (تنكتب «تجربة»)؛ والمشرف بس يحفظها للقطاع (قراءة + كتابة).
- **أولويات التعزيز** = الخطط مرتبة بالنسبة ثم بالأمبير غير القابل للاستعادة، والتصفية (رقم، تصنيف، مستوى، جهد، أقل من 100%، بديل يتجاوز سعته، تجريبي فقط/بدون) تمشي على المؤشرات والجدول والخريطة وملف CSV مع بعض.
- **التفاصيل**: ضغطة على رئيسي = تفاصيل خطته (ولو هو بديل لغيره ينذكر تحتها)؛ ضغطة على بديل-فقط = بطاقته: كل رئيسي يدعمه، وكم ياخذ منه، وتحميله بعدها.
- **الشارة فوق**: «بيانات فعلية» لو فيه خطة وحدة على الأقل مو تجريبية، «بيانات تجريبية» لو كلها معلّمة `demo`، ولا شي لو ما فيه خطط. وبدون خطط تطلع بطاقة هادئة في نص الخريطة («أضف أول خطة تغذية بديلة» + إضافة خطة / اختر من الخريطة / إدخال جماعي + سطر التغطية) والطبقات المستوردة تبقى شغالة وراها؛ العضو يشوفها بدون الأزرار.
- **الإضافة والتعديل**: المشرف يضيف الخطة (المستوى، الجهد، الرقم والحمل، البدائل بالترتيب) والنتيجة تنحسب قدامه وهو يكتب. أرقام المحطات تنكمل من **فهرس المحطات** حق الطبقات المستوردة بدون ولا قراءة.
- التخزين: مستند واحد لكل قطاع `backupPlans/{sectorId}` = `{ sectorId, visibility: 'restricted', ratingA, cases[], updatedAt }` (`src/services/backupPlans.ts`، والمنطق الصافي في `backupPlanDoc.ts`). **ينقرأ عند فتح الصفحة = قراءة وحدة**، وبعدها 10 دقايق بدون قراءة (نسخة في المتصفح مربوطة بالحساب وتنمسح عند تسجيل الخروج). الحفظ/التعديل/الحذف/سعة القاطع = قراءة + كتابة (يقرأ آخر نسخة قبل ما يكتب، والتعديلات المتزامنة تنكتب بالدور). اختيار خطة أو محطة، والتصفية، وتبديل الافتراضات = **صفر قراءات**. لو القواعد رفضت قراءة الخطط يرجع المستخدم للبوابة.
- **الموقع بالضبط والاختيار من الخريطة**: نفس رقم المحطة ممكن يكون على أكثر من نقطة، فكل عنصر في الخطة يقدر يحفظ نقطته `at: [lng, lat]` (ومعها `layerId`) وتنرسم الخطة عندها؛ الخطط القديمة بدونها تنرسم عند أول موقع في الفهرس مثل قبل. لو الرقم المكتوب له أكثر من موقع يطلع «يوجد n مواقع بهذا الرقم» وتختار (المرور على الخيار يأشر عليه في الخريطة)، ولو له موقع واحد ينحفظ بدون سؤال. زر «اختر من الخريطة» يطوي النموذج لشريط تعليمات ويرسم **كل محطات الفهرس** مربعات تنضغط (الرئيسي ثم البدائل بالترتيب، والضغط على مختار يشيله، وEsc يلغي) — من الفهرس مباشرة: **صفر قراءات** وبدون تغيير الطبقات المفعّلة ولا مكان الخريطة. ترتيب البدائل يتغير بأسهم فوق/تحت (المنطق الصافي في `backup/draft.ts` و`backup/directory.ts`).
- **التجريبي**: زر «أحمال تجريبية» يعبّي الخانات **الفاضية فقط** (الرئيسي 320 أمبير والبدائل 270، 285، 260، 250، 275 بالدور) ويحط على الخطة `demo: true` — تطلع عليها شارة «تجريبي» في القائمة والتفاصيل والجدول وتلميح الخريطة وعمود `demo` في الـ CSV لين ينشال صح «خطة تجريبية» من النموذج.
- **الإدخال الجماعي** (للمشرف — من «إدارة البيانات» أو لوحة الخطط أو البطاقة الفاضية): يختار أو يسحب ملف Excel ‏`.xlsx` مباشرة، أو يلصق أسطر منسوخة من Excel (مفصولة بـ Tab)، وملف `.csv` لسا مقبول. **الأعمدة**: `الرئيسي، حمل الرئيسي، بديل ١، حمل ١، بديل ٢، حمل ٢، بديل ٣، حمل ٣ …` (أي عدد من البدائل) + اختياري `المستوى، الجهد، السعة، ملاحظة` (و`demo`). سطر العناوين اختياري وينعرف بالعربي أو الإنجليزي وبأي ترتيب (وملف Excel أو CSV اللي تصدّره اللوحة ينقرأ رجوع، وأعمدة النتائج فيه تنتجاهل)؛ بدون عناوين: الرئيسي وحمله ثم أزواج البدائل، والمستوى «محطة» والجهد 13.8. الأرقام العربية وفواصل الآلاف مقبولة، والأسطر الفاضية تنتخطى. زر «تنزيل نموذج Excel للتعبئة» يطلع `نموذج-خطط-التغذية-البديلة.xlsx`: ورقة من اليمين لليسار بعناوين عريضة مثبّتة وأرقام كأرقام وسطرين مصطنعين، وورقة «تعليمات». ولوحة الخطط فيها «تصدير Excel» جنب «تصدير CSV»: نفس أعمدة النموذج (بعدد البدائل الموجود) وبعدها النتائج المحسوبة بعناوين رمادية، فالملف يتعدّل في Excel ويرجع يندخل. **قراءة xlsx وكتابته بدون مكتبة جداول**: الملف zip فيه XML، فـ`backup/xlsxRead.ts` و`backup/xlsxWrite.ts` يستخدمون `fflate` (الموجودة أصلاً للـ KMZ) وماسح XML صغير `backup/xmlScan.ts`، وكلها داخل ملفات الإدخال الجماعي اللي ما تنطلب إلا لما تنفتح النافذة أو ينضغط التصدير. القارئ يفهم النصوص المشتركة والمنسّقة والمضمّنة، والأرقام والقيم المنطقية، ونتيجة المعادلة المحفوظة (مو المعادلة نفسها)، ويحط كل خلية بمرجعها (`C5`) فالصفوف المتفرقة والخلايا الفاضية ما تلخبط، ويتخطى عناوين مدموجة فوق سطر العناوين، ويلقى الأوراق من `workbook.xml.rels`؛ لو فيه أكثر من ورقة تنفع ياخذ أول ورقة فيها سطر سليم ويطلع «الورقة: …» مع اختيار غيرها، والأوراق المخفية تنترك. **ما ينقرأ**: `.xls` القديم و`.xlsb` و`.xlsm` والملف المحمي بكلمة مرور والتالف — رسالة عربية بسيطة تطلب حفظه `.xlsx` (والسبب الحقيقي في `console.warn`)، وملف أكبر من 10 ميغا أو ورقة فوق 20,000 سطر ينرفض برسالة. ملف فيه معادلات ما انفتح في Excel أبداً (ما فيه نتائج محفوظة) تطلع أسطره «الحمل مفقود». قبل الحفظ **معاينة**: حالة كل سطر (سليم / رقم مو موجود في المحطات المستوردة — ينحفظ وما ينرسم / رقم له أكثر من موقع — ينحفظ بدون `at` وينذكر «بحاجة إلى تحديد الموقع» لين ينحدد من «تعديل» / رئيسي له خطة أو مكرر في الأسطر — استبدال أو تخطي، والافتراضي تخطي / سطر ما ينقرأ — ما ينحفظ ويقول ليش) + نسبة كل سطر + مجموع اللي بينحفظ ومجموع القطاع بعد الحفظ. المحلّل `backup/bulkParse.ts` (ياخذ نص أو مصفوفة خلايا — نفس المسار للّصق وCSV وExcel) والفحص `backup/bulkReview.ts` وقارئ xlsx وكاتبه دوال صافية مختبرة. **الكلفة**: اللصق والمعاينة صفر، والحفظ = **قراءة وحدة + كتابة وحدة** مهما كان عدد الخطط (`saveBackupCases`).
- **حذف بيانات الشبكة التجريبية القديمة** (للمشرف — «إدارة البيانات»): يحذف مستندات القطاع اللي `visibility: 'public'` في `networkBundles` و`ties` و`feeders` و`substations`، ومستند `sectors/{id}` **فقط لو هو `public`** (لو مقيّد يبقى). أي شي `restricted` ما ينلمس. النافذة تحصر أول وتعرض الأعداد بالضبط، ثم تحذف على دفعات (400 في الدفعة) مع شريط تقدّم، ولو انقطعت «متابعة» تحصر الباقي وتكمّل. **الكلفة**: فتح النافذة = قراءة لكل مستند تلقاه (الشبكة المصطنعة كاملة ≈ 19 + 95 + 44 + 1 حزمة + 1 قطاع = **160 قراءة**، وعلى الأقل قراءة لكل مجموعة لو فاضية = 5)، والحذف = **حذف لكل مستند (≈ 160)** بدون قراءات زيادة. عملية لمرة وحدة (`services/legacyNetwork.ts`).

> **الأرقام الفعلية (أرقام المحطات وأحمالها) مكانها قاعدة البيانات فقط** — تنكتب من الواجهة بحساب مشرف، وما تدخل الكود ولا الاختبارات ولا الأمثلة. كل اللي في الريبو أرقام مصطنعة (7001، 7002…).

- **وضوح خريطة الأساس**: أسماء الشوارع جزء من صور البلاطات، فالخريطة كلها تنبهّت بـ CSS عشان المحطات والنقاط تبرز. من «طبقات الخريطة» شريط بثلاث درجات (باهت — الافتراضي، متوسط، واضح) ينحفظ في المتصفح (`sanad.rc.basemap`) وما يعيد تحميل الخريطة ولا البلاطات. مصدر البلاطات المخصص (`VITE_MAP_TILE_URL`) ينعرض كما هو.

### استيراد طبقات الخريطة (KMZ / KML)

المشرف فقط يشوف قائمة «إدارة البيانات» في الشريط العلوي، وأول ما فيها «استيراد طبقات الخريطة»:

1. يختار ملف Google Earth (`.kmz` أو `.kml`) من جهازه. الملف ينقرأ **داخل المتصفح** (`src/features/restoration/import/` — دوال صافية بدون Firebase) وما يمر على أي سيرفر.
2. تطلع معاينة: كل مجلد في الملف = طبقة، مع عدد النقاط والخطوط والمناطق. جولة Google Earth الافتراضية والطبقات البعيدة عن القطاع تجي بدون تحديد.
3. «استيراد» يكتب الطبقات المحددة على Firestore مباشرة (`src/services/mapLayers.ts`): وصف الطبقة في `mapLayers` وعناصرها مقسّمة في `mapLayerChunks` (كل جزء أقل من 700KB)، ودائماً بـ `visibility: 'restricted'`، وينضاف وصفها لفهرس القطاع `mapLayerIndex`. استيراد نفس المجلد مرة ثانية يستبدل الطبقة.
4. الطبقات تظهر في «طبقات الخريطة ← طبقات مستوردة» لأعضاء القطاع فقط، وعناصر الطبقة ما تنحمّل إلا لما تتفعّل.
5. **فهرس المحطات**: أي نقطة اسمها يبدأ برقم محطة من أربع خانات (`S/S 7001`، `S/S_8123`، `7001`…) تنحسب محطة (`import/stations.ts`)، ورقمها واسمها وموقعها ينكتبون مع وصف الطبقة داخل `mapLayerIndex` وقت الاستيراد — فالبحث برقم المحطة في «طبقات مستوردة» ما يقرأ ولا مستند. الطبقات المستوردة قبل هالميزة يتجهّز فهرسها تلقائياً مرة وحدة أول ما يفتح المشرف الصفحة (يقرأ أجزاء كل طبقة مرة، ويكتب الفهرس مرة وحدة في الآخر، ولو انقطع يكمّل من وين ما وقف).
6. **المجلدات الفرعية**: المجلدات اللي داخل مجلد الطبقة تنحفظ مع كل عنصر في الحقل `g` (مثل `11kV / Phase 2`) وتطلع كمجموعات لما تفتح محتويات الطبقة. الطبقات المستوردة قبل كذا ما فيها `g`، فلازم **تنعاد استيرادها** عشان تطلع مجموعاتها (المحطات ما تحتاج إعادة استيراد).
7. **تحديد الكل**: مربع بثلاث حالات فوق قائمة الطبقات يفعّل/يلغي الطبقات **المعروضة في القائمة** (نتائج البحث لو فيه بحث)، ويتخطى الطبقات الفاضية. الطبقات اللي ما انقرأت تنحمّل 4 في المرة مع سطر واحد «جارٍ تحميل الطبقات… 18 / 107»، وضغطة ثانية توقف الباقي؛ الكلفة = أجزاء كل طبقة مرة وحدة في الجلسة، واللي انقرأ قبل يتبدّل فوراً بدون قراءة.
8. **الطبقات المكررة** (للمشرف فقط): لو الملف فيه نفس المجلد مرتين تطلع «توجد n طبقات مكررة» + «حذف المكرر». المكرر = نفس الاسم (بدون لاحقة ` (n)`) **و**نفس الأعداد والحدود وعدد المحطات — ينكشف من الفهرس بدون قراءة (`layerDuplicates.ts`)، ويبقى الأقدم استيراداً. التأكيد يعرض اللي يبقى واللي ينحذف، والحذف بالدور ويوقف عند أول فشل؛ الكلفة لكل طبقة = استعلام أجزائها + حذفها وحذف وصفها، والفهرس ينقرأ وينكتب **مرة وحدة** في الآخر (`deleteMapLayers`).

> **ملفات المصدر (KMZ/KML) ما تدخل الريبو أبداً** — لا في `public/` ولا `src/` ولا الاختبارات ولا كأمثلة، ولا أي شي مشتق منها (أسماء، إحداثيات، أوصاف). أي تجربة على ملف حقيقي تكون خارج مجلد المشروع.

### المحطات: وين تنحفظ، وكيف تدخل وتطلع (Excel)

**وين تنحفظ**: ما فيه مجموعة «محطات» مستقلة. المحطة = نقطة في طبقة مستوردة اسمها يبدأ برقمها (`S/S 7001`)، ورقمها واسمها وموقعها (و`FLOCSAP` لو معروف — رقم المحطة في نظام SAP، نص كما هو) تنكتب في **فهرس المحطات** داخل `mapLayerIndex/{sectorId}` وقت حفظ الطبقة. الصفحة تبني منه «دليل المحطات» في الذاكرة (`backup/directory.ts`)، فكل شي تحت — البحث، القوائم المنسدلة، رسم الخطط، التصدير — يشتغل **بدون أي قراءة**.

**ثلاث طرق تدخل فيها المحطات**:

1. ملف Google Earth (فوق).
2. **استيراد محطات من Excel** («إدارة البيانات» ← للمشرف): أعمدة `رقم المحطة، FLOCSAP، الاسم، خط العرض، خط الطول، الطبقة` — العناوين بالعربية أو الإنجليزية وبأي ترتيب، وبدون عناوين تُقرأ الأربعة الأولى (رقم، اسم، عرض، طول). المعاينة تقول عن كل سطر: جديدة / موجودة بالموقع نفسه (تُتجاوز) / الرقم موجود بموقع آخر (تُضاف موقعاً إضافياً، مع تنبيه) / تحديث FLOCSAP / خارج نطاق القطاع (ما تُستورد إلا لو حدّدت «استيراد الصفوف خارج النطاق أيضاً») / مقلوبة (خط العرض والطول بالعكس، مع زر تبديل) / غير صالحة. الحفظ يمر بنفس مسار حفظ الطبقة (`saveMapLayer`): الأسطر تصير نقاط في طبقة اسمها من عمود «الطبقة» (الافتراضي «محطات مضافة يدوياً»)، وتحديث FLOCSAP يُكتب في طبقة المحطة نفسها. إدخال نفس الملف مرتين ما يكرر شي. النموذج: «تنزيل نموذج Excel للتعبئة» داخل نفس النافذة (`نموذج-المحطات.xlsx`). الكلفة لكل طبقة تتغير: قراءة أجزائها (لو ما كانت محمّلة) + استعلام أجزائها للحذف + قراءة الفهرس؛ وكتابة أجزائها الجديدة + وصفها + الفهرس. طبقة يدوية جديدة صغيرة = قراءتان و3 كتابات.
3. **ورقة «المحطات» في ملف الخطط** (تحت) — ما تحتاج استيراد مستقل.

**طريقتان تطلع فيها**: «تصدير المحطات إلى Excel» (`محطات-<القطاع>.xlsx`: كل موقع لكل محطة مع `لها خطة` و`نسبة الاستعادة ٪` من الخطط — متاح للعضو أيضاً من رأس «طبقات مستوردة» لأنه ما يقرأ شي) وتصدير الخطط إلى Excel (فيه ورقة «المحطات» نفسها).

**نموذج الخطط بقوائم منسدلة** (`نموذج-خطط-التغذية-البديلة.xlsx`، من «إدخال جماعي للخطط»): يتبنى في المتصفح من دليل المحطات. أعمدة «الرئيسي» و«بديل ١…٥» فيها **تحقق بيانات من نوع قائمة** يشير إلى عمود الأرقام في ورقة «المحطات» (`'المحطات'!$A$2:$A$N`، وباسم `StationNumbers`)، مع تنبيه من نوع «تحذير» عشان يظل ممكن كتابة رقم جديد؛ الأحمال رقم ≥ 0، «المستوى» قائمة `محطة/مغذي`، «الجهد» قائمة `13.8/33`. ورقة «المحطات» فيها كل رقم مرة وحدة بموقعه الأول (الأرقام اللي لها أكثر من موقع مظللة وتفاصيلها في ورقة «مواقع مكررة») وتحتها 200 سطر فارغ بتحقق للإحداثيات: **تكتب رقم محطة جديدة وإحداثياتها هناك** فتُضاف للخريطة عند إدخال الملف وتصير متاحة كرئيسي أو بديل. عند الإدخال الجماعي تنقرأ ورقة «المحطات» مع ورقة الخطط: الجديدة والمعدّلة تطلع في المعاينة في كتلة «محطات جديدة أو معدّلة» (بمربعات اختيار)، وتُحفظ **قبل** الخطط بنفس مسار الاستيراد، والخطة اللي تستخدم رقماً منها تاخذ موقعه بالضبط فتنرسم فوراً. لو فشل حفظ المحطات ما تُكتب الخطط. بدون طبقات مستوردة ينزل النموذج بأسطر المثال وورقة محطات فاضية والنافذة تقول ليش. ملف الخطط المصدَّر فيه نفس القوائم ونفس الورقة، وأعمدة `FLOCSAP الرئيسي / FLOCSAP بديل n` نتائج للاطلاع ما تنقرأ عند الإدخال. الكاتب في `backup/xlsxWrite.ts` (يكتب `<dataValidations>` و`<definedNames>` وتنسيق النص `@` للـ FLOCSAP والإحداثيات بست خانات)، والورقة في `backup/stationSheet.ts`، والقراءة في `stationParse.ts` و`stationReview.ts`.

### ميزانية القراءة من Firestore

الخطة المجانية تعطي **50,000 قراءة مستند في اليوم**، وكل مستند ينقرأ = قراءة، ولو خلصت الحصة ترجع كل القراءات مرفوضة لين تتجدد. عشان كذا كل شي تحتاجه الصفحة عند الفتح = **مستندين**: الخطط وفهرس الطبقات.

- **الخطط `backupPlans/{sectorId}`**: مستند واحد فيه كل خطط القطاع = قراءة وحدة عند فتح الصفحة مهما كثرت الخطط، وهي الشبكة اللي تنعرض (شوف «الشبكة المشتقة من الخطط» فوق). **حزمة الشبكة** `networkBundles` والمستندات التفصيلية (`sectors` / `substations` / `feeders` / `ties`) **ما عاد تنقرأ من اللوحة أبداً**؛ كودها (`services/restoration.ts` و`networkBundle.ts`) باقي لاستيراد مستوى المغذيات مستقبلاً، والمستندات المصطنعة القديمة تنحذف من «إدارة البيانات».
- **نسخة محفوظة في المتصفح** (`localStorage`، المفاتيح `sanad.rc.plans.<sectorId>` و`sanad.rc.layers.<sectorId>` و`sanad.rc.sectors` — في `src/services/cache.ts`): أول 10 دقايق بعد القراءة ما فيه أي قراءة. النسخة مربوطة بالحساب وتنمسح عند تسجيل الخروج (ومعها أي نسخة قديمة خلّتها الإصدارات السابقة، مثل `sanad.rc.network.*`).
- **فهرس الطبقات `mapLayerIndex/{sectorId}`**: مستند واحد فيه أوصاف كل الطبقات المستوردة، فالقائمة = قراءة وحدة مهما كثرت الطبقات. الاستيراد والحذف يحدّثونه بالدور (الطبقات اللي تخلص مع بعض تنكتب في تحديث واحد)، ولو الفهرس مو موجود يبنيه المشرف مرة وحدة من `mapLayers`. عناصر الطبقة نفسها ما تنقرأ إلا لما تتفعّل، ومرة وحدة في الجلسة.
- **فحص التصريح** (`admins/{uid}` ثم `members/{uid}`): قراءة أو قراءتين في الجلسة عند البوابة، وأزرار المشرف تعتمد على نفس النتيجة بدون قراءة زيادة (الصلاحية الفعلية عند قواعد Firestore).
- **قائمة القطاعات**: تبدأ من السجل المبني في الكود (`sectors.ts`)، والمشرف يقرأ مجموعة `sectors` (قراءة لكل مستند، وعلى الأقل وحدة لو فاضية) والعضو يقرأ مستند كل قطاع في قائمته — للأسماء وللقطاعات اللي ما يعرفها السجل فقط — وتنحفظ 10 دقايق. لو المجموعة فاضية أو تعذّرت قراءتها تشتغل الصفحة من السجل.
- **لو تعذّر الوصول لقاعدة البيانات** (الحصة خلصت، النت مقطوع، مهلة 8 ثواني): تنعرض آخر نسخة محفوظة من الخطط مع تنبيه هادئ، ولو ما فيه نسخة تنعرض الصفحة بدون خطط مع نفس التنبيه — **ما فيه بيانات مصطنعة تنعرض مكانها أبداً**. القراءات كلها `getDocsFromServer` (في `src/services/reads.ts`) عشان «ما فيه بيانات» ما تختلط مع «ما قدرنا نسأل».
- الكلفة المتوقعة لفتح الصفحة: غير المسجّل = **صفر** دائماً. مسجّل غير مصرّح = 2 (الفحص فقط). مشرف = 1 (الفحص) + 1 (الخطط) + 1 (فهرس الطبقات) + القطاعات، ثم 0 لعشر دقايق. عضو = 2 + 1 + 1 + قراءة لكل قطاع في قائمته. (أقل بقراءتين من قبل: حزمتين الشبكة ما عاد تنقرأ.) في وضع التطوير (`npm run dev`) يطلع في الـ console سطر `[reads]` بعدد المستندات المقروءة من فتح الصفحة — لو شفته بالمئات فيه شي رجع يقرأ مستند مستند.

> **الاختبارات الآلية (puppeteer وغيره) ما تشتغل أبداً على قاعدة البيانات الحية ولا على `sanadgrid.com`.** ابنِ نسخة بدون إعدادات Firebase — متغيرات البيئة الفاضية تغلب `.env.local` — وشغّل الاختبار عليها:
>
> ```bash
> VITE_E2E_OPEN=1 VITE_FIREBASE_API_KEY= VITE_FIREBASE_PROJECT_ID= VITE_FIREBASE_APP_ID= npm run build && npm run preview
> ```
>
> بدون `VITE_E2E_OPEN=1` تطلع البوابة بحالة «غير متاحة» ولا شي غيرها. معه تفتح اللوحة فاضية (بطاقة «لا توجد خطط تغذية بديلة بعد» وبدون شارة بيانات)، والاختبار نفسه يتأكد إن ما طلع ولا طلب لـ `firestore.googleapis.com` / `identitytoolkit` / `securetoken`. المفتاح ما له أي أثر في نسخة فيها مفاتيح Firebase (شوف «الصفحة خاصة» فوق). منطق القراءة والكتابة ينختبر على قاعدة بيانات وهمية في الذاكرة، مو على الحية.
