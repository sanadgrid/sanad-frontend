# sanad — Frontend

React + Vite + TypeScript، ينشر على Netlify تلقائياً مع كل `push` على `main`.

الباك اند (قواعد Firestore) في ريبو منفصل: [sanad-backend](https://github.com/sanadgrid/sanad-backend).

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local   # ثم عبّي قيم Firebase
npm run dev
```

قيم Firebase من: Firebase Console ← ⚙ Project settings ← Your apps ← Web app ← SDK setup and configuration.

## ربط Netlify (مرة واحدة)

1. Netlify ← **Add new site** ← **Import an existing project** ← GitHub ← اختر `sanadgrid/sanad-frontend`.
2. إعدادات البناء تنقرأ تلقائياً من `netlify.toml` (الأمر `npm run build`، المجلد `dist`).
3. Site configuration ← **Environment variables** ← أضف متغيرات `VITE_FIREBASE_*` الستة الموجودة في `.env.example`.
4. Deploy. بعدها أي push على `main` ينشر تلقائياً، وأي Pull Request ياخذ رابط معاينة.
5. Firebase Console ← Authentication ← Settings ← **Authorized domains** ← أضف دومين Netlify.

> لو فشل البناء برسالة "secrets scanning" بسبب مفتاح يبدأ بـ `AIza`: مفتاح Firebase للويب عام بطبيعته (الحماية من قواعد Firestore). أضف في Netlify متغير `SECRETS_SCAN_SMART_DETECTION_OMIT_VALUES` وقيمته هي المفتاح.

## هيكلة الكود — طبقات

كل طبقة تستورد من اللي تحتها فقط، مو العكس:

```
src/
  app/        غلاف التطبيق: التوجيه والـ providers
  features/   شاشات ومزايا، كل ميزة في مجلدها (features/home, ...)
  components/ مكونات واجهة مشتركة بين المزايا (Logo, Icon) — بدون بيانات
  services/   الوصول للبيانات — المكان الوحيد اللي يكلم Firestore
  lib/        تهيئة البنية التحتية (firebase.ts للتطبيق وتسجيل الدخول، firestore.ts لقاعدة البيانات)
```

- نصوص وأرقام الصفحة الرئيسية كلها في `src/features/home/content.ts` — عدّلها هناك بدون لمس التصميم.
- ألوان وخطوط الهوية في `src/index.css`، وملفات اللوقو الجاهزة في `public/brand/`.
- صورة المشاركة (واتساب وغيره) هي `public/og-image.jpg` ووسومها في `index.html`. الرابط الكامل ينحقن وقت البناء من متغير `URL` حق Netlify (شوف `vite.config.ts`). المعاينة ما تظهر إلا والموقع Public.
- المكونات في `features/` ما تستدعي Firestore مباشرة؛ تنادي دوال من `services/`.
- أي collection جديدة = ملف في `services/` هنا + قاعدة في `firestore.rules` في ريبو الباك اند.
- مفاتيح الـ AI أو أي سر ما تنحط هنا أبداً — كل شي في الفرونت مكشوف للمتصفح. استدعاءات الـ LLM تمر عبر Cloud Function في ريبو الباك اند.

## لوحة قدرة استعادة الخدمة — `/restoration`

لوحة تخطيط تشغيلي: لكل محطة تحسب كم من حملها تقدر المحطات المجاورة تشيله عبر نقاط الربط المفتوحة عادةً لو فُقدت المحطة بالكامل (N-1)، حسب الشهر والسيناريو.

- **الصفحة خاصة** — ما تفتح إلا لمستخدم مسجّل دخوله ومصرّح له (التفاصيل في «الصفحة خاصة — بوابة الدخول» تحت).
- الكود كله في `src/features/restoration/`. `src/app/App.tsx` يحمّل **البوابة** فقط عند الطلب (`RestorationGate.tsx`)، والبوابة هي اللي تحمّل اللوحة (`RestorationPage` ومعها Leaflet وFirestore والبيانات التجريبية) بعد ما يتأكد التصريح.
- **محرك الحساب** في `engine.ts` — دوال صافية بدون I/O، تشتغل في المتصفح أو في Cloud Function بدون تغيير. **نموذج البيانات** في `types.ts` ويطابق مستندات Firestore (شوف `docs/data-model.md` في ريبو الباك اند).
- **البيانات التجريبية** في `demoData.ts`: شبكة مصطنعة للقطاع الأوسط (رموز المحطات والأحمال والسعات ونقاط الربط كلها مختلقة، والحقيقي فقط أسماء الأحياء ومواقعها التقريبية). تظهر **للمصرّح له فقط** (بعد البوابة) لو القطاع ما انتشرت بياناته أو تعذّرت القراءة — والشارة فوق تبيّن المصدر. غير المصرّح له ما يشوفها ولا ينزّل ملفها.
- القراءة والكتابة في `src/services/` فقط. ما فيه أي قراءة بدون تسجيل دخول: القواعد ترفض الكل إلا المشرف أو عضو القطاع، حتى المستندات التجريبية اللي `visibility: 'public'` (الحقل باقي للتمييز بين التجريبي والفعلي، بس ما عاد يفتح القراءة).
- خريطة الأساس OpenStreetMap معتّمة بـ CSS. لو عندك مفتاح لمزوّد خرائط داكنة حط رابطه في `VITE_MAP_TILE_URL` (شوف `.env.example`).

> **البيانات الفعلية ما تنحط في هذا الريبو أبداً** — الريبو عام وكل شي فيه مكشوف. البيانات الفعلية تنرفع على Firestore فقط، من مشرف مسجّل دخوله (له مستند في `admins/{uid}`)، وبـ `visibility: 'restricted'` عشان ما يقرأها إلا أعضاء القطاع. زر «رفع البيانات التجريبية» في اللوحة يرفع الشبكة المصطنعة فقط.

### الصفحة خاصة — بوابة الدخول

`/restoration` ما تعرض أي شي — لا خريطة ولا مؤشرات ولا بيانات تجريبية ولا حتى كود اللوحة — إلا بعد شرطين: المستخدم **مسجّل دخوله** و**مصرّح له**.

**كيف ينعطى التصريح** (من Firebase Console ← Firestore، قاعدة `sanadgrid`، والـ uid من Authentication ← Users):

- **مشرف**: مستند `admins/{uid}` (فاضي يكفي). ينشأ من الـ Console فقط — القواعد تمنع كتابته من أي مكان ثاني. يشوف كل القطاعات ويقدر يكتب.
- **عضو**: مستند `members/{uid}` فيه `sectors: ["central", ...]`. يشوف القطاعات اللي في قائمته فقط (وهي اللي تطلع له في قائمة «القطاع»)، وما يكتب شي. `sectors` فاضية أو مو موجودة = غير مصرّح.
- التغيير يسري من الجلسة الجاية (المستخدم يقفل التبويب أو يسجّل خروج ويرجع)، وسحب التصريح يسري فوراً على القراءة لأن القواعد هي اللي تقرر — وأول قراءة تنرفض ترجّع المستخدم للبوابة.

**حالات البوابة** (`RestorationGate.tsx` — بطاقة وحدة في النص، بالوضعين الفاتح والداكن):

| الحالة | اللي يطلع |
| --- | --- |
| جارٍ التحقق | الشعار ومؤشر انتظار هادئ فقط |
| غير مسجّل | «هذه الصفحة مخصصة للمستخدمين المصرّح لهم» + زر تسجيل الدخول بحساب Google + رابط للرئيسية — بدون أي تلميح عن محتوى الصفحة |
| مسجّل وغير مصرّح | «حسابك غير مصرّح له…» + بريد الحساب + «تجربة حساب آخر» و«تسجيل الخروج» + «تواصل مع مسؤول النظام» |
| تعذّر التحقق (نت/حصة/مهلة) | «تعذّر التحقق من الصلاحية الآن» + «إعادة المحاولة» — **ما تنحسب أبداً تصريح** |
| نسخة بدون إعدادات Firebase | «هذه الصفحة غير متاحة حالياً» |

- **الفحص** في `src/services/access.ts` (منطق صافي ومختبر) والقراءتين في `accessReads.ts`: `admins/{uid}` أولاً، ولو مو مشرف `members/{uid}`. الكلفة: **قراءة وحدة للمشرف، قراءتين لغيره، مرة في الجلسة**. الـ«نعم» بس تنحفظ في `sessionStorage` (`sanad.rc.access.<uid>` — مربوطة بالحساب)، والـ«لا» تبقى لين تتقفل الصفحة، والفشل ما ينحفظ أبداً. الفحوصات المتزامنة تتشارك قراءة وحدة. هذا كله يقرر **اللي ينعرض** فقط — اللي ينقرأ فعلاً تقرره قواعد Firestore، فلو أحد عبث بالمتصفح ما يوصل لشي.
- **اللي ينزّله غير المسجّل**: الصفحة الأساسية + البوابة + مكتبة تسجيل الدخول. ملفات اللوحة وLeaflet وFirestore والبيانات التجريبية ما تنطلب إلا بعد التصريح (مجموعات `codeSplitting` في `vite.config.ts` تفصل `firebase` عن `firestore` لهالسبب).
- **تسجيل الخروج** من داخل اللوحة يرجّع للبوابة فوراً ويمسح كل اللي انقرأ: نسخة الشبكة والقطاعات وفهرس الطبقات والخطط من `localStorage` والذاكرة، وتصريح الجلسة من `sessionStorage` (`clearDataCache` في `cache.ts`). تفضيلات الشكل (الوضع، وضوح الخريطة) تبقى.
- **ما ننشر عنوان الصفحة**: ما فيه رابط لها في الصفحة الرئيسية، و`netlify.toml` يرسل `X-Robots-Tag: noindex, nofollow` لـ `/restoration`، والبوابة تضيف `<meta name="robots">` طول ما الصفحة مفتوحة، وعنوان التبويب يبقى «سند | SanadGrid» لين يمر المستخدم من البوابة.
- **الاختبارات بدون Firebase**: `npm test` يختبر منطق التصريح والكاش بدون أي اتصال. واختبارات المتصفح تشتغل على نسخة مبنية **بدون مفاتيح Firebase** — وهذي النسخة تطلع فيها البوابة بحالة «غير متاحة»، فلها مفتاح اختبار `VITE_E2E_OPEN=1` يفتح اللوحة على البيانات التجريبية (و`?gate=signedOut|denied|unverified|checking` يعرض حالات البوابة للتصوير). المفتاح **ما يشتغل إلا والمفاتيح غايبة**: `vite.config.ts` يحوّله لـ `false` ثابتة في أي نسخة فيها مفاتيح، فكوده أصلاً ما يدخل نسخة الإنتاج.

### مستويان للحساب: المحطة والمغذي — وخطط التغذية البديلة

اللوحة تجاوب على نفس السؤال بمستويين:

- **مستوى المحطة (MVA)** — محرك `engine.ts`: لو فُقدت المحطة كاملة، كم يرجع عبر نقاط الربط مع مراعاة سعة الربط والمغذي المستقبِل والسعة المؤكدة للمحطة المستقبِلة والتخفيض الحراري.
- **مستوى المغذي (أمبير)** — `backup/model.ts`: نفس طريقة جدول فريق التشغيل حرفياً. عنصر رئيسي حمله `C`، وبدائل أحمالها `a1..an`، وسعة قاطع `R` (الافتراضي 400 أمبير): المتاح عند كل بديل `max(0, R − a)`، القابل للاستعادة `min(C, Σ المتاح)`، والتحويل يتوزع على البدائل بالترتيب وبنسبة المتاح عند كل واحد. التصنيف بنفس حدود اللوحة (100% / 70% / أكثر من صفر). الخيارات: `ratingA` و`derating` (يضرب السعة؛ 1 = طريقة الجدول كما هي). التحويل بين الأمبير وMVA في مكان واحد: `backup/units.ts` (`√3 · kV · A / 1000`).
- **اختبار المعايرة** (`backup/model.test.ts`): مثال الفريق المصطنع (30 مغذي في 3 قطاعات) لازم يطلع بالضبط: مجموع الأحمال 8,755 أمبير، غير القابل للاستعادة **525 أمبير**، النسبة **94.0%**، التصنيف 9 كامل / 21 مرتفع — ومع سعة 348 أمبير يصير 3,475 (60.3%)، ومع 320 يصير 5,155 (41.1%). أي تعديل على النموذج يكسر هالأرقام = النموذج ما عاد يطابق الجدول.
- **الجسر بين المستويين** (`backup/fromNetwork.ts`): من تفاصيل أي محطة تختار مغذي فتطلع بطاقة «عند فقد المغذي»: بدائله هي المغذيات اللي على الطرف الثاني من نقاط ربطه، بأحمال الفترة والسيناريو المحددين محوّلة لأمبير، في جدول بنفس أعمدة جدول الفريق. فيها مفتاحان **مقفولان افتراضياً** عشان الأرقام تطابق الجدول: «تطبيق التخفيض الحراري للشهر المحدد» و«مراعاة السعة المؤكدة للمحطة المستقبِلة».
- **خطط التغذية البديلة** («المحطة الرئيسية كذا، البديل الأول كذا، البديل الثاني كذا»): تظهر للمسجّلين فقط، من خيارات التصفية أو من أزرار الخريطة. المشرف يضيف الخطة (المستوى، الجهد، الرقم والحمل، البدائل بالترتيب) والنتيجة تنحسب قدامه وهو يكتب. أرقام المحطات تنكمل من **فهرس المحطات** حق الطبقات المستوردة بدون ولا قراءة، ومنه تجي الإحداثيات اللي تنرسم بها الخطة على الخريطة (الرئيسي بحلقة، والبدائل مرقّمة ١ ٢ ٣، ولون الخط حسب تحميل البديل بعد التحويل). في تفاصيل الخطة مفتاح «تطبيق التخفيض الحراري» يعرض النتيجة قبل وبعد جنب بعض — هذي أهم معلومة: النتيجة حساسة جداً لسعة القاطع.
- التخزين: مستند واحد لكل قطاع `backupPlans/{sectorId}` = `{ sectorId, visibility: 'restricted', ratingA, cases[], updatedAt }` (`src/services/backupPlans.ts`، والمنطق الصافي في `backupPlanDoc.ts`). ما ينقرأ شي لين تنفتح لوحة الخطط أول مرة؛ فتحها = **قراءة وحدة**، وبعدها 10 دقايق بدون قراءة (نسخة في المتصفح مربوطة بالحساب وتنمسح عند تسجيل الخروج). الحفظ/التعديل/الحذف = قراءة + كتابة (يقرأ آخر نسخة قبل ما يكتب، والتعديلات المتزامنة تنكتب بالدور). اختيار خطة يفعّل الطبقة اللي فيها محطاتها لو ما كانت مفعّلة (= قراءة أجزاء هالطبقة مرة وحدة في الجلسة).
- **الموقع بالضبط والاختيار من الخريطة**: نفس رقم المحطة ممكن يكون على أكثر من نقطة، فكل عنصر في الخطة يقدر يحفظ نقطته `at: [lng, lat]` (ومعها `layerId`) وتنرسم الخطة عندها؛ الخطط القديمة بدونها تنرسم عند أول موقع في الفهرس مثل قبل. لو الرقم المكتوب له أكثر من موقع يطلع «يوجد n مواقع بهذا الرقم» وتختار (المرور على الخيار يأشر عليه في الخريطة)، ولو له موقع واحد ينحفظ بدون سؤال. زر «اختر من الخريطة» يطوي النموذج لشريط تعليمات ويرسم **كل محطات الفهرس** مربعات تنضغط (الرئيسي ثم البدائل بالترتيب، والضغط على مختار يشيله، وEsc يلغي) — من الفهرس مباشرة: **صفر قراءات** وبدون تغيير الطبقات المفعّلة ولا مكان الخريطة. ترتيب البدائل يتغير بأسهم فوق/تحت (المنطق الصافي في `backup/draft.ts` و`backup/directory.ts`).
- **التجريبي**: زر «أحمال تجريبية» يعبّي الخانات **الفاضية فقط** (الرئيسي 320 أمبير والبدائل 270، 285، 260، 250، 275 بالدور) ويحط على الخطة `demo: true` — تطلع عليها شارة «تجريبي» في القائمة والتفاصيل وعمود `demo` في الـ CSV لين ينشال صح «خطة تجريبية» من النموذج. و**الشبكة التجريبية** (الدوائر الكبيرة المصطنعة) **مخفية افتراضياً**: مفتاحها آخر «طبقات الخريطة» (`sanad.rc.demoNetwork`) ويطلع بس لو الشبكة المحمّلة `visibility: 'public'`؛ وهي مخفية تصير المؤشرات وأولويات التعزيز «لا توجد بيانات شبكة فعلية بعد»، وتنطوي خياراتها تحت «خيارات الشبكة التجريبية»، وتفتح الخريطة على الخطة المختارة وإلا على حدود محطات الفهرس.

> **الأرقام الفعلية (أرقام المحطات وأحمالها) مكانها قاعدة البيانات فقط** — تنكتب من الواجهة بحساب مشرف، وما تدخل الكود ولا الاختبارات ولا الأمثلة. كل اللي في الريبو أرقام مصطنعة (7001، 7002…).

- **وضوح خريطة الأساس**: أسماء الشوارع جزء من صور البلاطات، فالخريطة كلها تنبهّت بـ CSS عشان المحطات والنقاط تبرز. من «طبقات الخريطة» شريط بثلاث درجات (باهت — الافتراضي، متوسط، واضح) ينحفظ في المتصفح (`sanad.rc.basemap`) وما يعيد تحميل الخريطة ولا البلاطات. مصدر البلاطات المخصص (`VITE_MAP_TILE_URL`) ينعرض كما هو.

### استيراد طبقات الخريطة (KMZ / KML)

المشرف فقط يشوف زر «استيراد طبقات الخريطة» في الشريط العلوي:

1. يختار ملف Google Earth (`.kmz` أو `.kml`) من جهازه. الملف ينقرأ **داخل المتصفح** (`src/features/restoration/import/` — دوال صافية بدون Firebase) وما يمر على أي سيرفر.
2. تطلع معاينة: كل مجلد في الملف = طبقة، مع عدد النقاط والخطوط والمناطق. جولة Google Earth الافتراضية والطبقات البعيدة عن القطاع تجي بدون تحديد.
3. «استيراد» يكتب الطبقات المحددة على Firestore مباشرة (`src/services/mapLayers.ts`): وصف الطبقة في `mapLayers` وعناصرها مقسّمة في `mapLayerChunks` (كل جزء أقل من 700KB)، ودائماً بـ `visibility: 'restricted'`، وينضاف وصفها لفهرس القطاع `mapLayerIndex`. استيراد نفس المجلد مرة ثانية يستبدل الطبقة.
4. الطبقات تظهر في «طبقات الخريطة ← طبقات مستوردة» لأعضاء القطاع فقط، وعناصر الطبقة ما تنحمّل إلا لما تتفعّل.
5. **فهرس المحطات**: أي نقطة اسمها يبدأ برقم محطة من أربع خانات (`S/S 7001`، `S/S_8123`، `7001`…) تنحسب محطة (`import/stations.ts`)، ورقمها واسمها وموقعها ينكتبون مع وصف الطبقة داخل `mapLayerIndex` وقت الاستيراد — فالبحث برقم المحطة في «طبقات مستوردة» ما يقرأ ولا مستند. الطبقات المستوردة قبل هالميزة يتجهّز فهرسها تلقائياً مرة وحدة أول ما يفتح المشرف الصفحة (يقرأ أجزاء كل طبقة مرة، ويكتب الفهرس مرة وحدة في الآخر، ولو انقطع يكمّل من وين ما وقف).
6. **المجلدات الفرعية**: المجلدات اللي داخل مجلد الطبقة تنحفظ مع كل عنصر في الحقل `g` (مثل `11kV / Phase 2`) وتطلع كمجموعات لما تفتح محتويات الطبقة. الطبقات المستوردة قبل كذا ما فيها `g`، فلازم **تنعاد استيرادها** عشان تطلع مجموعاتها (المحطات ما تحتاج إعادة استيراد).
7. **تحديد الكل**: مربع بثلاث حالات فوق قائمة الطبقات يفعّل/يلغي الطبقات **المعروضة في القائمة** (نتائج البحث لو فيه بحث)، ويتخطى الطبقات الفاضية. الطبقات اللي ما انقرأت تنحمّل 4 في المرة مع سطر واحد «جارٍ تحميل الطبقات… 18 / 107»، وضغطة ثانية توقف الباقي؛ الكلفة = أجزاء كل طبقة مرة وحدة في الجلسة، واللي انقرأ قبل يتبدّل فوراً بدون قراءة.
8. **الطبقات المكررة** (للمشرف فقط): لو الملف فيه نفس المجلد مرتين تطلع «توجد n طبقات مكررة» + «حذف المكرر». المكرر = نفس الاسم (بدون لاحقة ` (n)`) **و**نفس الأعداد والحدود وعدد المحطات — ينكشف من الفهرس بدون قراءة (`layerDuplicates.ts`)، ويبقى الأقدم استيراداً. التأكيد يعرض اللي يبقى واللي ينحذف، والحذف بالدور ويوقف عند أول فشل؛ الكلفة لكل طبقة = استعلام أجزائها + حذفها وحذف وصفها، والفهرس ينقرأ وينكتب **مرة وحدة** في الآخر (`deleteMapLayers`).

> **ملفات المصدر (KMZ/KML) ما تدخل الريبو أبداً** — لا في `public/` ولا `src/` ولا الاختبارات ولا كأمثلة، ولا أي شي مشتق منها (أسماء، إحداثيات، أوصاف). أي تجربة على ملف حقيقي تكون خارج مجلد المشروع.

### ميزانية القراءة من Firestore — الحزمة والفهرس

الخطة المجانية تعطي **50,000 قراءة مستند في اليوم**، وكل مستند ينقرأ = قراءة. لو الصفحة قرأت القطاع مستند مستند (1 قطاع + 19 محطة + 95 مغذي + 44 ربط = 159 قراءة لكل فتحة صفحة، غير أوصاف الطبقات) تخلص الحصة بسرعة، وساعتها كل القراءات ترجع مرفوضة لين تتجدد الحصة. عشان كذا:

- **حزمة الشبكة `networkBundles/{sectorId}_{visibility}_{index}`**: القطاع كامل (القطاع + المحطات + المغذيات + نقاط الربط) نص JSON واحد في الحقل `payload`، ينقسم لأجزاء كل جزء أقل من 700KB (الشبكة التجريبية جزء واحد ~35KB). كل جزء يحمل `count` و`version` (وقت النشر). المصرّح له يقرأ حزمة `public` (التجريبية) وحزمة `restricted` (الفعلية) باستعلامين فيهم `sectorId`، وتندمج الشبكتين (المقيّد يغلب لو تكرر المعرّف). غير المصرّح له ما يقرأ ولا وحدة. المنطق الصافي في `src/services/networkBundle.ts`.
- **المستندات التفصيلية** (`sectors` / `substations` / `feeders` / `ties`) تبقى مصدر الحقيقة للتعديل، والحزمة تنبني منها: «نشر البيانات التجريبية» يكتب الاثنين، و`publishBundle(sectorId)` يعيد بناء الحزمة من المستندات. لو قاعدة البيانات ما فيها حزمة ودخل **مشرف**، الصفحة تقرأ المستندات مرة وحدة وتنشر الحزمة تلقائياً — غير المشرف ما يقرأ المستندات التفصيلية أبداً (يشوف البيانات التجريبية لين تنبني الحزمة).
- **نسخة محفوظة في المتصفح** (`localStorage`، المفتاح `sanad.rc.network.<sectorId>` — في `src/services/cache.ts`): الصفحة تنعرض منها فوراً. أول 10 دقايق ما فيه أي قراءة؛ بعدها قراءة لكل حزمة (الجزء 0) تقارن `version`، وما ينقرأ الباقي إلا لو تغيّر. النسخة مربوطة بالحساب وتنمسح عند تسجيل الخروج (ومعها أي نسخة قديمة خلّتها الإصدارات السابقة).
- **فهرس الطبقات `mapLayerIndex/{sectorId}`**: مستند واحد فيه أوصاف كل الطبقات المستوردة، فالقائمة = قراءة وحدة مهما كثرت الطبقات. الاستيراد والحذف يحدّثونه بالدور (الطبقات اللي تخلص مع بعض تنكتب في تحديث واحد)، ولو الفهرس مو موجود يبنيه المشرف مرة وحدة من `mapLayers`. عناصر الطبقة نفسها ما تنقرأ إلا لما تتفعّل، ومرة وحدة في الجلسة.
- **فحص التصريح** (`admins/{uid}` ثم `members/{uid}`): قراءة أو قراءتين في الجلسة عند البوابة، وأزرار المشرف تعتمد على نفس النتيجة بدون قراءة زيادة (الصلاحية الفعلية عند قواعد Firestore).
- **قائمة القطاعات**: المشرف يقرأ مجموعة `sectors` كاملة، والعضو يقرأ مستند كل قطاع في قائمته (قراءة لكل قطاع) لأن القواعد ترفض له المجموعة كاملة — وتنحفظ 10 دقايق.
- **لو تعذّر الوصول لقاعدة البيانات** (الحصة خلصت، النت مقطوع، مهلة 8 ثواني): تنعرض النسخة المحفوظة وتبقى شارتها «بيانات مباشرة» مع تنبيه هادئ، ولو ما فيه نسخة تنعرض البيانات التجريبية مؤقتاً. القراءات كلها `getDocsFromServer` (في `src/services/reads.ts`) عشان «ما فيه بيانات» ما تختلط مع «ما قدرنا نسأل».
- الكلفة المتوقعة: غير المسجّل = **صفر** دائماً. مسجّل غير مصرّح = 2 (الفحص فقط). مشرف = 1 (الفحص) + 2 (الحزمتين) + القطاعات + فهرس الطبقات أول مرة في الجلسة، ثم 0 لعشر دقايق. عضو = 2 + 2 + قراءة لكل قطاع في قائمته + الفهرس. في وضع التطوير (`npm run dev`) يطلع في الـ console سطر `[reads]` بعدد المستندات المقروءة من فتح الصفحة — لو شفته بالمئات فيه شي رجع يقرأ مستند مستند.

> **الاختبارات الآلية (puppeteer وغيره) ما تشتغل أبداً على قاعدة البيانات الحية ولا على `sanadgrid.com`.** ابنِ نسخة بدون إعدادات Firebase — متغيرات البيئة الفاضية تغلب `.env.local` — وشغّل الاختبار عليها:
>
> ```bash
> VITE_E2E_OPEN=1 VITE_FIREBASE_API_KEY= VITE_FIREBASE_PROJECT_ID= VITE_FIREBASE_APP_ID= npm run build && npm run preview
> ```
>
> بدون `VITE_E2E_OPEN=1` تطلع البوابة بحالة «غير متاحة» ولا شي غيرها. معه لازم تشوف الشارة «بيانات عامة تجريبية»، والاختبار نفسه يتأكد إن ما طلع ولا طلب لـ `firestore.googleapis.com` / `identitytoolkit` / `securetoken`. المفتاح ما له أي أثر في نسخة فيها مفاتيح Firebase (شوف «الصفحة خاصة» فوق). منطق القراءة والكتابة ينختبر على قاعدة بيانات وهمية في الذاكرة، مو على الحية.
